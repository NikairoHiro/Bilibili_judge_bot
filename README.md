# BiliAtMonitor

> 一个零依赖的 B站「@我的」消息监控与 AI 辩证回复机器人。
> A zero-dependency Python bot that watches your Bilibili @-mentions, judges the comments with an LLM, and replies.

纯 Python 标准库实现，**不需要 `pip install` 任何东西**。它定时读取消息中心的 @，
解析被 @ 的评论及其上下文，交给大模型判断对方是在陈述事实、论证观点、表达立场还是情绪输出，
再按预设规则决定回不回、怎么回、回给谁。

> 本项目与哔哩哔哩、DeepSeek 官方均无关联，仅供个人学习与自用。

## 特性

- **抓取**：轮询 `x/msgfeed/at`，把 @ 人、@ 的视频、父级评论一并记录到固定 txt（原地更新，不新建文件）
- **上下文**：读取父级评论 + 父级所回复的那条评论，@ 发起者的原话也一并纳入判断
- **AI 判定**：事实类联网查证、论点类查逻辑谬误并核对论据真伪、情绪类文明回怼、只表态类指出缺失证据
- **安全过滤**：政治 / 民族 / 两岸等敏感话题直接拒绝，不把内容送进模型；提示词注入本地拦截
- **次数与信用**：每个 @ 我的人两个 0~3 的计数，按日 / 按周重置，归零后不再实质回复
- **持久化队列**：一个事件只回一条，回复发出并经平台验证后出队；不同事件可对同一评论各回一条
- **风险控制**：最小间隔、每小时 / 每日上限、风控熔断、夜间静默、黑白名单、关注校验
- **本地网页控制台**：启动 / 停止、队列、报表、用户、实时日志、扫码登录
- **零依赖**：只用标准库，单文件即可运行

## 快速开始

### 1. 准备 DeepSeek API Key

项目**不内置任何密钥**。任选一种方式提供：

```bat
set DEEPSEEK_API_KEY=sk-xxxxxxxx        :: 方式一：环境变量（推荐）
python bili_at_monitor.py --ai --ai-key sk-xxxxxxxx   :: 方式二：命令行
:: 方式三：网页控制台「设置」里填写，会存进 gui_config.json
```

### 2. 登录 B站

```bat
python bili_at_monitor.py --login
```

终端会生成二维码（同时写出 `qr_login.png` / `qr_login.html`），用 B站 App 扫码即可。
凭证保存在 `cookie.txt` 和 `_state.json`。

### 3. 先试运行（不发评论）

```bat
python bili_at_monitor.py --ai --once
```

只判断、只打印，不发送。确认措辞可接受后再进入下一步。

### 4. 正式运行

```bat
python bili_at_monitor.py --ai --reply --interval 300
```

## 回复规则

收到一条 @ 后按下列顺序判断，**顺序即优先级**：

| # | 情况 | 回复 | 回复对象 | 扣减 |
| --- | --- | --- | --- | --- |
| 0 | 该用户没有关注本账号 | 「你并没有关注我，却跑来让我评判，这算「错误」了」 | @ 人 | 不扣 |
| 0 | 今日回复配额已用完 | 「今天我能安全回复的配额已经用完了（n/上限）」 | @ 人 | 不扣 |
| 0 | 该用户信用为 0 | 「你的信用已经为 0 了……是「错误」的」 | @ 人 | 不扣 |
| 0 | 该用户次数为 0 | 「你今天找我的次数已经用完了……是「错误」的」 | @ 人 | 不扣 |
| 1 | 命中安全屏蔽词（政治 / 民族 / 两岸等） | 固定拒绝语，**内容不进入模型** | @ 人 | 信用 −1 |
| 2 | @ 评论本身是直接评论视频的一级评论 | 「你这话是对着视频本身说的……是「错误」的」 | @ 人 | 信用 −1 |
| 3 | 含提示词注入 | 「真是「错误」呢——想用几句话就操纵我？」 | @ 人 | 信用 −1 |
| 4 | 闲聊 / 灌水 | 「这属于闲聊，不是在讲道理；与我闲聊是「错误」的」 | @ 人 | 信用 −1 |
| 5 | 纯情绪 / 骂人 | 调用模型，按其原话文明回怼 | 父级评论 | 次数 −1 |
| 6 | 只有观点、没有证据 | 调用模型，指出它缺少哪些证据 | 父级评论 | 次数 −1 |
| 7 | 在陈述事实 | 联网检索后回复查证结果 | 父级评论 | 次数 −1 |
| 8 | 在论证观点 | 查逻辑谬误 **+ 联网核对论据**：有问题回「你这段话有「错误」」，无问题回「你这段话是「正确」的」 | 父级评论 | 次数 −1 |

补充说明：

- 回复末尾会自动追加扣减提示，如 `今日次数-1，当前次数为 2/3`
- 固定话术每个分支准备了多套等价说法轮换，降低 B站「重复评论 12051」概率
- 判定由语言模型完成，存在波动；置信度低时会二次判定并按确定性规则裁决
- 所有固定文案集中在 `deepseek_judge.py` 顶部，可直接修改（含一句带调侃意味的固定回复）

## 次数与信用

每个 @ 过本账号的用户都有两个计数，初值 3，范围 0~3：

| 计数 | 何时减少 | 何时重置 |
| --- | --- | --- |
| 次数 | 每次正常回答 | 每天 |
| 信用 | 每次被拒答 | 每周 |

归零后不再对其作出实质回复，直到重置。数据保存在 `user_credits.csv`。

可选「特权 UID」：通过 `--free-user` 或环境变量 `BILI_FREE_UID` 指定一名用户，
其计数永不减少，回复中的数值显示为 `∞`。**默认不启用。**

## 回复队列

待回复事件进入 `_state.json` 的 `reply_queue`，逐条处理：

- **按事件去重**：一个 @ 事件只回一条；不同事件可对同一评论各回一条
- **验证后出队**：发出后到平台确认（重试 3 次），确认存在才写入 `done`，该事件不再回队列
- **失败保留**：网络 / 风控 / 配额等临时失败留在 `pending`，下一轮继续；连续失败 5 次才丢弃
- **评论已删除**：丢弃并记录原因
- `done` 上限 2000 条，超出按时间淘汰

## 配置

### 主要命令行参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--ai` | 关 | 开启 AI 判定模式 |

| `--once` | 关 | 只跑一轮 |

| `--ai-max-per-hour` | 8 | 每小时回复上限 |

| `--quiet-hours` | 空 | 夜间静默，如 `23:00-07:00` |

| `--free-user` | 空 | 特权 UID（不扣减，显示 ∞） |

| 变量 | 说明 |

## 安全与合规

**请在使用前阅读：**

1. **这是用你自己的账号在说话。** 自动回复陌生人可能被判定为骚扰或刷屏，账号存在被限流、禁言的风险。建议先用小号验证，或把 `--ai-max-per-day` 调到 10 以下。
2. **不要用于刷屏、引战或骚扰特定用户。** 项目内置的次数 / 信用、黑白名单、夜间静默和频率限制就是为此设计的，请勿全部关闭。
3. **敏感话题会被拒绝。** 涉及政治、民族、两岸等内容的评论不会进入模型，直接回固定话术。屏蔽词表在 `deepseek_judge.py` 的 `SAFETY_WORDS`，可按需调整。
4. **事实核查仅供参考。** 联网查证基于搜索引擎摘要，可能滞后或引用失当，不构成权威结论。
5. **凭证安全。** `cookie.txt` / `_state.json` 等同于账号密码，不要提交、不要上传、不要发给他人。
6. **遵守平台规则。** 使用本项目即表示你自行承担由此产生的全部后果，包括但不限于账号处罚。

## 已知限制

- **看不到视频和图片**：对一级评论只知其存在，无法分析视频内容；评论中的图片、表情包同样无法读取
- **判定有波动**：分类由模型给出，同一条评论两次结果可能不同（已用置信度二次判定缓解）
- **事实核查较浅**：仅有搜索摘要，不校验来源权威性与时效性
- **不理解反讽**：可能按字面意思处理
- **Cookie 会失效**：B站服务端可能提前作废会话，需要重新扫码
- **仅支持单账号**：没有多账号隔离

## 常见问题

**Q：报 `-101 账号未登录`？**
A：SESSDATA 失效，重新执行 `python bili_at_monitor.py --login`。

**Q：报 `12051 重复评论`？**
A：B站判定内容重复。项目已对固定话术做多套轮换，仍偶发时会跳过该事件，等下一轮。

**Q：报 `12074 等级不足`？**
A：B站要求 LV2 以上才能评论。

**Q：控制台中文乱码？**
A：Windows 默认 GBK，用 `启动控制台.bat`（内部已 `chcp 65001`），或设置 `PYTHONIOENCODING=utf-8`。

**Q：想重跑已经回复过的事件？**
A：删除 `_state.json` 中 `reply_queue.done` 里对应的条目（或整个 `reply_queue`）。

**Q：为什么默认不发评论？**
A：默认 dry-run 是有意设计，先看判断和措辞，确认后再加 `--reply`。
